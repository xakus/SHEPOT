# План: чтение текста вслух (TTS) по правому Alt

Статус: **этапы 1–3 сделаны (2026-09-14), следующий — этап 4 (установщик и документы).**
План согласован 2026-09-14.
Обзор функции для пользователя — `docs/PROJECT.md`, раздел 4.

---

## 1. Цель и границы

**Делаем:** по одиночному нажатию правого Alt демон берёт текст из окна в
фокусе (выделение, иначе — от курсора до конца) и читает его вслух
голосом Piper. Повторное нажатие — стоп. Управление голосом/скоростью из
трея.

**Не трогаем:** весь путь диктовки (`Recorder`, `pump`, `transcriber`,
`make_typer`, `ModelManager`). В `shepot.py` добавляются только точки
стыковки (раздел 4.2). Если для чтения понадобится менять код диктовки —
стоп, вернуться к плану.

**Должно работать на слабых ПК:** без GPU, ≤ 200 МБ RAM сверх текущего,
первое слово ≤ 0.5 с после нажатия на среднем CPU.

---

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Клавиша | `KEY_RIGHTALT` (правый Alt), настраивается `SHEPOT_TTS_KEY` |
| Режим клавиши | одиночное нажатие = старт / стоп (не удержание) |
| Выделение | есть выделение → читать только его; нет → от курсора до конца |
| Источник текста | AT-SPI → откат на клавиши+буфер → (вручную) только буфер |
| Движок | Piper (`piper-tts` 1.8, wheel `cp39-abi3` — ставится под Python 3.14) → откат на `espeak-ng --stdout` |
| Голос по умолчанию | `ru_RU-irina-medium` |
| Где код | новый модуль `shepot_reader.py`; в `shepot.py` — только стыковка |

Проверено на машине Мурада 2026-09-14: `onnxruntime` 1.29 уже в venv;
AT-SPI доступен из Python (`gi.repository.Atspi`, 13 приложений на шине);
`ydotool` работает. `spd-say` **не работает**: поток speech-dispatcher в
PipeWire зависает в `init`, END не приходит — поэтому запасной движок
`espeak-ng` напрямую (решение изменено на этапе 1).

## 3. Сценарии использования

### 3.1. Читать от курсора
1. Курсор стоит в середине текста в gedit / LibreOffice / поле ввода браузера.
2. Нажал и отпустил правый Alt (ничего другого не нажимая).
3. Трей: иконка «чтение», статус «Читаю… 1/12». Слышен текст от курсора.
4. Дочитал до конца → статус «Готов», иконка обычная.

### 3.2. Читать выделенное
1. Выделил абзац мышью или Shift+стрелками.
2. Правый Alt → читается только абзац, после него — стоп.

### 3.3. Остановить
- Правый Alt во время чтения → стоп ≤ 0.1 с, очередь очищается.
- Правый Ctrl (начало диктовки) → чтение останавливается автоматически.
- Пункт «Стоп чтение» в трее.

### 3.4. Текста нет
- Фокус в терминале, на картинке, на рабочем столе → статус «Нет текста —
  поставь курсор в текст или выдели». Ничего не нажимается, ничего не
  ломается (в терминале ни один процесс не должен пострадать).

### 3.5. Комбинации с Alt
- Правый Alt + любая клавиша (AltGr+8, Alt+Tab и т.п.) → чтение **не**
  запускается: срабатывание только если между нажатием и отпусканием Alt
  не было других клавиш.

## 4. Архитектура

### 4.1. Новый модуль `shepot_reader.py`

```
shepot_reader.py
├── настройки SHEPOT_TTS_* (вверху файла, как в shepot.py)
├── split_blocks(text) -> list[str]        режет текст на блоки ≤ ~400 симв.
│                                          по пустым строкам / концам предложений
├── class TextSource                       интерфейс: grab() -> str | None
│   ├── class AtspiSource                  шина доступности
│   ├── class KeysSource                   эмуляция клавиш + буфер обмена
│   └── class ClipboardSource              только буфер
├── def pick_sources(mode) -> list[TextSource]   порядок по SHEPOT_TTS_SOURCE
├── class Engine                           интерфейс: synth(block, rate) -> iter[(np.float32, sr)]
│   ├── class PiperEngine                  piper-tts, ленивая загрузка голоса
│   └── class EspeakEngine                 espeak-ng --stdout → WAV → float32
├── class VoiceManager                     каталог голосов, скачивание, конфиг
└── class Reader                           конвейер: grab → blocks → synth → play
                                           toggle() / start(text) / stop()
```

### 4.2. Стыковка в `shepot.py` (минимум правок)

1. `find_keyboards()` — искать устройства и с `HOTKEY`, и с `TTS_KEY`
   (объединение списков).
2. В selectors-цикле `worker()`: сейчас `if ev.code != HOTKEY: continue`.
   Добавить ветку для `TTS_KEY` с логикой «одиночного нажатия» (раздел 8) →
   `reader.toggle()` в daemon-потоке. Остальные клавиши — как раньше.
3. При `ev.value == 1` для `HOTKEY` (начало диктовки) — `reader.stop()`.
4. `Tray`: чекбокс «Читать», пункт «Стоп чтение», подменю «Голос»,
   «Скорость», «Движок»; методы `set_voice_catalog()` по образцу
   `set_model_catalog()`.
5. `main()`: `reader = Reader(tray, config)`; передаётся в `worker()`.

Импорт: `import shepot_reader` — модуль лежит рядом с `shepot.py` в `~/bin`,
а каталог скрипта всегда первый в `sys.path`.

### 4.3. Потоки

```
evdev-цикл (worker)  ──toggle()──►  Reader
                                     ├─ grab-поток: источники по очереди (таймаут 2 с)
                                     ├─ synth-поток: блоки → engine.synth() → audio_q (maxsize=2)
                                     └─ play-поток:  audio_q → sd.OutputStream.write() кусками по 50 мс,
                                                     между кусками проверяет stop_flag
GTK main loop                         ◄── все обновления трея через GLib.idle_add
                                      ◄── AT-SPI-запросы выполняются здесь (раздел 5.1)
```

`audio_q` с `maxsize=2` — обратное давление: синтез не убегает вперёд,
память не растёт на длинных текстах.

## 5. Источники текста

Порядок при `SHEPOT_TTS_SOURCE=auto`: `AtspiSource` → `KeysSource`.
`ClipboardSource` — только если задан явно. Каждый источник возвращает
`None`, если текста нет; тогда пробуется следующий.

### 5.1. `AtspiSource`

- Инициализация при старте демона: `Atspi.init()`, `Atspi.set_timeout(800,
  15000)` — чтобы зависшее приложение не держало нас дольше 0.8 с.
- Слушатель `object:state-changed:focused` кэширует последний объект в
  фокусе (так делает Orca). События приходят через GLib main loop, который
  уже крутит `Gtk.main()` — отдельный поток не нужен.
- `grab()` вызывается из evdev-потока, но libatspi не потокобезопасна →
  запрос выполняется через `GLib.idle_add` в GTK-потоке, evdev-поток ждёт
  `threading.Event` с таймаутом 2 с.
- Алгоритм на объекте `acc` в фокусе:
  ```
  text = acc.get_text_iface()            # None → источник не подходит
  n = text.get_character_count()
  if text.get_n_selections() > 0:
      r = text.get_selection(0)
      if r.end_offset > r.start_offset:  return text.get_text(r.start_offset, r.end_offset)
  caret = max(text.get_caret_offset(), 0)
  s = text.get_text(caret, n)
  ```
- Если кэш пуст (фокус сменился до старта демона) — обход активного окна
  (`STATE_ACTIVE` → потомок со `STATE_FOCUSED`), не более 3000 узлов.
- Если результат пустой или > 25 % символов `U+FFFC` (веб-страница: текст
  разложен по дочерним узлам) → `None`, идём к `KeysSource`. Обход дерева
  веб-документа — v2 (раздел 15).
- **Целиком читаем только роли `text`, `entry`, `editbar`** (GtkTextView,
  поля ввода, textarea). LibreOffice Writer даёт фокус отдельному абзацу
  (и в дереве только видимые абзацы) — от курсора до конца документа через
  AT-SPI не взять → `None`, клавиши.
- **Терминал (`terminal`) и поле пароля (`password text`) → `NO_TEXT`**:
  цепочка останавливается. VTE на любой запрос Text строит текст всего
  буфера прокрутки (секунды) и, пока занят, не отвечает даже на запрос
  буфера обмена — из-за этого `KeysSource` в терминале висел 27 с. Пароли
  вслух не читаем.
- **Возврат курсора после клавиш:** при своём проходе AT-SPI запоминает
  `(объект, позиция курсора)`; если текст в итоге взяли клавиши через
  Ctrl+Shift+End, курсор возвращается `Atspi.Text.set_caret_offset()`. Нужно
  для Writer: там `←` после выделения оставляет курсор в конце документа.
- Firefox/Chrome строят дерево лениво: первый запрос его «будит». Если
  активное окно есть, а объекта с фокусом нет — повтор через 300 мс.
- Обход дерева ограничен 3000 узлами **и 1.5 с** — зависшее приложение не
  должно держать GTK-поток (в демоне это поток трея).
- Firefox / Chrome включают доступность только при
  `org.gnome.desktop.interface toolkit-accessibility = true` (у Мурада
  сейчас `false`) — ставит установщик; браузеры нужно перезапустить.

### 5.2. `KeysSource`

Тем же механизмом, что вставка в `make_typer()`: X11 → `xdotool key`,
Wayland → `ydotool key` скан-кодами; буфер — `wl-copy`/`wl-paste` или
`xclip`.

```
1. old = буфер обмена (текст; картинку/файлы восстановить нельзя — теряем, документируем)
2. wl-copy "<соль>"  (уникальная строка, напр. "⁣shepot-tts-<uuid>")
   ждать подтверждения через wl-paste (как в make_typer, таймаут 3 с)
3. Ctrl+Insert                        → ждать ≤ 0.4 с, изменился ли буфер
   изменился  → это выделение → text = буфер → шаг 6
4. Ctrl+Shift+End, Ctrl+Insert        → ждать ≤ 0.6 с
   изменился  → text = буфер (от курсора до конца)
   не изменился → text = None (текста нет)
5. ←  (Left)                          → снять выделение, курсор на прежнее место
6. wl-copy old                        → вернуть буфер
```

Скан-коды (evdev): `KEY_LEFTCTRL=29`, `KEY_LEFTSHIFT=42`, `KEY_END=107`,
`KEY_INSERT=110`, `KEY_LEFT=105`. Строки для ydotool задаются переменными
`SHEPOT_TTS_KEYS_COPY`, `SHEPOT_TTS_KEYS_SELECT_END`, `SHEPOT_TTS_KEYS_LEFT`
(раздел 9), чтобы менять без правки кода.

Почему `Ctrl+Insert`, а не `Ctrl+C`: в терминале Ctrl+C = SIGINT — убьёт
запущенную программу. Ctrl+Insert в GNOME Terminal ничего не делает, а в
редакторах, браузерах, LibreOffice, VS Code — копирует.

Буфер обмена сохраняется **вместе с MIME-типом** (`wl-paste --list-types`
→ `--type`): картинка `image/png` возвращается байт в байт (проверено).
Ожидание «есть ли выделение?» — 0.4 с, «от курсора до конца» — 0.8 с;
итого источник занимает 0.6 с (выделение) … 1.4 с (от курсора).

Ловушка: `wl-copy`/`xclip` при записи оставляют фоновый процесс-владелец
буфера, который наследует наши пайпы — `subprocess.run(capture_output=True)`
на записи ждёт их закрытия вечно. Запись — только с `DEVNULL`.

Защита от гонки с диктовкой: `KeysSource.grab()` и `make_typer()` оба
трогают буфер обмена; чтение не стартует, пока идёт вставка распознанного
текста (общий `threading.Lock` на буфер в `shepot_reader`, `make_typer` его не
знает — достаточно того, что `reader.stop()` зовётся при нажатии правого
Ctrl, а вставка идёт после отпускания, когда чтение уже остановлено).

### 5.3. `ClipboardSource`

`SHEPOT_TTS_SOURCE=clipboard`: читать текущее содержимое буфера. Для программ,
где не работает ни AT-SPI, ни эмуляция клавиш: пользователь копирует сам.

## 6. Движки

### 6.1. `PiperEngine` (основной)

Проверенный API `piper-tts` 1.8.0:
```python
from piper import PiperVoice, SynthesisConfig
voice = PiperVoice.load(onnx_path, config_path=None, use_cuda=False)
for chunk in voice.synthesize(block, SynthesisConfig(length_scale=1/rate)):
    chunk.audio_float_array   # np.float32 в [-1, 1]
    chunk.sample_rate         # 22050 для medium-голосов
```
`synthesize()` — генератор, **одно предложение за итерацию**: следующее
предложение синтезируется, когда мы за ним придём. Блоки (`split_blocks`)
нужны, чтобы espeak-ng не фонемизировал 20 000 символов разом перед первым
звуком.

- Сессию ONNX собираем сами (не `PiperVoice.load()`), с
  `enable_cpu_mem_arena = False`: арена растёт до размера самого длинного
  предложения и не отдаёт память (замер: 350 симв. → 793 МБ навсегда; без
  арены пик 275 МБ, память возвращается; синтез медленнее на ~20 %).
- Загрузка голоса ленивая — при первом `synth()`; `SHEPOT_TTS_PRELOAD=1` —
  при старте. После загрузки голос остаётся в памяти. Прогрев фразой
  «Готово.» — первый вызов ONNX в разы медленнее.
- Смена голоса — как смена модели Whisper: задание в очереди Reader'а,
  выгрузка старого, загрузка нового, при ошибке — откат.
- `length_scale = 1 / rate` (`rate` 0.8 … 2.0).
- Ошибка загрузки (нет файла, битый onnx) → статус в трее + откат на
  `SpdEngine` до перезапуска.

### 6.2. `EspeakEngine` (запасной)

`espeak-ng -v ru -s <слов/мин> --stdout -- "<блок>"` в subprocess → WAV в
stdout → int16 → float32 → тот же плеер, что у Piper. Скорость: 175 слов/мин
× rate. Выбирается при `SHEPOT_TTS_ENGINE=espeak` или если `import piper` не
удался. Нет ни Piper, ни espeak-ng → статус «Чтение недоступно: pip install
piper-tts или apt install espeak-ng».

Почему не `spd-say` (первоначальный план): на машине Мурада поток
`speech-dispatcher-espeak-ng` в PipeWire (с Easy Effects) висит в `[init]`,
звука нет, `-w` ждёт вечно (замер: 105 с на фразу из 64 символов). Свой
плеер надёжнее и даёт один путь стопа.

### 6.3. `VoiceManager`

По образцу `ModelManager`:
- каталог — `voices.json` с HuggingFace (`rhasspy/piper-voices`), фильтр
  `ru_RU-*`; размеры файлов есть в каталоге; офлайн-список по умолчанию:
  `irina`, `denis`, `dmitri`, `ruslan` (все `medium`, ≈ 60 МБ каждый);
- скачивание своим `urllib` с прогрессом в статус трея (URL берём из
  `piper.download_voices.URL_FORMAT`, чтобы не дублировать формат);
- папка `SHEPOT_TTS_VOICES_DIR` (по умолчанию `~/.local/share/shepot/voices`);
- удаление скачанного (кроме активного), «Открыть папку голосов»;
- выбор в `config.json`: `tts_voice`.

## 7. Воспроизведение (`Reader`)

- `split_blocks(text)`: сначала по пустым строкам, затем блоки длиннее
  `SHEPOT_TTS_BLOCK` (300) символов режутся по концу предложения (`.!?…`),
  затем — по `;`, `,`, `:`; совсем без знаков — по пробелу; одно «слово» длиннее
  лимита — как есть. Блоки без букв и цифр («---») выбрасываются. Пустые/пробельные блоки выкидываются. Считаем
  блоки: статус «Читаю… i/N».
- Обрезка: если `len(text) > SHEPOT_TTS_MAX_CHARS` → читаем первые N символов,
  статус «Читаю… (обрезано до 20 000 симв.)».
- `play`-поток: один `sd.OutputStream(samplerate=sr, channels=1,
  dtype="float32")` на сессию чтения; пишет кусками по 50 мс и проверяет
  `stop_flag` — стоп ощущается мгновенно. Микрофонный `InputStream` в
  `Recorder` не трогаем — PortAudio/PipeWire спокойно держат оба.
- `stop()`: флаг → очистить `audio_q` → `stream.abort()` → дождаться потоков
  (join ≤ 1 с) → статус «Готов».
- Иконка во время чтения: `audio-speakers-symbolic` (константа `ICON_READ`).
- Лог в stdout: `ЧТЕНИЕ: 1234 симв., 7 блоков, источник=atspi` и по каждому
  блоку `синтез 2.1 с аудио за 0.15 с` — по этим цифрам проверяем
  производительность на слабом ПК.

## 8. Горячая клавиша

В evdev-цикле `worker()` для `TTS_KEY` (`ev.code == 100`):

```
value 1 (нажата):   alt_down = True;  alt_solo = True
любая другая клавиша, value 1, пока alt_down:  alt_solo = False
value 0 (отпущена): if alt_down and alt_solo and tray.tts_enabled:
                        threading.Thread(target=reader.toggle, daemon=True).start()
                    alt_down = False
value 2 (автоповтор): игнорировать
```

Так `AltGr+8`, `Alt+Tab` и прочие комбинации не запускают чтение.

**Побочный эффект одиночного Alt** в приложениях (Firefox показывает меню,
LibreOffice переносит фокус в меню): демон не может его убрать без захвата
всей клавиатуры. Лечение — на уровне раскладки, по желанию:
```bash
gsettings set org.gnome.desktop.input-sources xkb-options "['lv3:ralt_switch']"
```
Правый Alt становится AltGr (ISO_Level3_Shift): программы перестают видеть
в нём Alt, а evdev по-прежнему отдаёт `KEY_RIGHTALT`. В установщик не
включаем (меняет клавиатуру пользователя), описываем в README. Альтернатива
без побочных эффектов — `SHEPOT_TTS_KEY=KEY_PAUSE`.

Чекбокс «Читать (KEY_RIGHTALT)» в трее — как «Слушать» для диктовки;
состояние в `config.json` (`tts_enabled`).

## 9. Настройки

### 9.1. Переменные окружения (новые)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SHEPOT_TTS_KEY` | `KEY_RIGHTALT` | клавиша чтения (имя из `evdev.ecodes`) |
| `SHEPOT_TTS_ENGINE` | `auto` | `auto` (piper, иначе espeak) / `piper` / `espeak` |
| `SHEPOT_TTS_VOICE` | `ru_RU-irina-medium` | голос Piper; выбор в трее приоритетнее |
| `SHEPOT_TTS_RATE` | `1.0` | скорость 0.5 … 2.0 |
| `SHEPOT_TTS_SOURCE` | `auto` | `auto` (atspi→keys) / `atspi` / `keys` / `clipboard` |
| `SHEPOT_TTS_MAX_CHARS` | `20000` | лимит длины текста |
| `SHEPOT_TTS_PRELOAD` | — | если задана — грузить голос при старте |
| `SHEPOT_TTS_VOICES_DIR` | `~/.local/share/shepot/voices` | папка голосов |
| `SHEPOT_TTS_BLOCK` | `300` | макс. длина блока, симв.; на слабом ПК 150–200 — ниже пик памяти и задержка |
| `SHEPOT_TTS_KEYS_COPY` | `29:1 110:1 110:0 29:0` | Ctrl+Insert для ydotool |
| `SHEPOT_TTS_KEYS_SELECT_END` | `29:1 42:1 107:1 107:0 42:0 29:0` | Ctrl+Shift+End |
| `SHEPOT_TTS_KEYS_LEFT` | `105:1 105:0` | ← |

### 9.2. `config.json` (новые ключи)

## 11. Установка (`install-shepot.sh`)

- apt: `+ gir1.2-atspi-2.0 espeak-ng` (atspi уже стоит у Мурада, espeak-ng —
  нет; на чистой машине нужны оба).
- pip: `+ piper-tts` (тянет `pathvalidate`; `onnxruntime` уже есть).

  ru_RU-irina-medium --data-dir ~/.local/share/shepot/voices` (≈ 60 МБ,

- В финальном сообщении: «правый Alt — чтение; если Alt мешает в
  Firefox/LibreOffice — см. README, lv3:ralt_switch».

`shepot-run.sh` не меняется.

## 12. Слабые компьютеры — конкретно

| Мера | Эффект |
|---|---|
| Piper medium на CPU, `use_cuda=False` | GPU не нужен; Piper проектировался под Raspberry Pi 4 |
| Синтез по предложениям, `audio_q(maxsize=2)` | первое слово через ~0.3 с; память постоянная |
| Ленивая загрузка голоса | демон без чтения не тратит RAM; после первого чтения +≈150 МБ |
| `split_blocks` ≤ 300 симв. (`SHEPOT_TTS_BLOCK`) | espeak-ng не фонемизирует весь текст перед первым звуком; ниже пик памяти ONNX |
| арена onnxruntime выключена | память не растёт до размера самого длинного предложения |
| `SHEPOT_TTS_MAX_CHARS` | нельзя случайно синтезировать мегабайт |
| Никакого torch / silero / кокоро | зависимости: `onnxruntime` + `piper-tts` (~30 МБ) |
| `EspeakEngine` | совсем слабая машина: espeak-ng, ~0 RAM |

**Факт (этап 1, 2026-09-14, i7 / 8 потоков):** загрузка голоса 1.0 с; 38.5 с
речи за 2.5 с (x15); память после чтения 241 МБ; транзитный пик до ~440 МБ
на худшем предложении в 300 символов (17 с речи), после блока память
возвращается. Ожидание для двухъядерного Celeron — ≈ 3–4× реального времени.

## 14a. Смена клавиш из меню трея (добавлено 2026-09-14 по просьбе Мурада)

До этого клавиши задавались только переменными `SHEPOT_KEY`/`SHEPOT_TTS_KEY`.
Теперь их можно менять из трея; env остаются как значения по умолчанию.

- **Способ:** подменю «Клавиша диктовки» и «Клавиша чтения» со списком
  безопасных редких клавиш (radio-выбор), отфильтрованным по тем, что реально
  есть на клавиатуре. Не «нажми любую клавишу» — так нельзя случайно
  назначить букву/Enter и сломать печать. Список кандидатов: правый
  Ctrl / Alt / Shift / Super, Menu, Pause, Scroll Lock, Caps Lock, Insert.
- **Защита:** одну клавишу нельзя назначить и на диктовку, и на чтение —
  выбор занятой клавиши отклоняется со статусом, меню возвращается.
- **Применение на лету:** демон регистрирует все физические клавиатуры
  (устройства с буквой A или спец-клавишей, **кроме виртуального
  `ydotoold`** — иначе демон ловил бы свои же синтетические нажатия) и в
  evdev-цикле сравнивает код с текущими `tray.dictate_key`/`tray.read_key`.
  Смена клавиши = обновить эти поля + конфиг; перезапуск не нужен.
- **Конфиг:** ключи `hotkey`, `tts_key` (имена вида `KEY_RIGHTCTRL`).
  Приоритет: конфиг → env (`SHEPOT_KEY`/`SHEPOT_TTS_KEY`) → умолчание.
- **Меню:** лейблы чекбоксов «Слушать (…)» / «Читать (…)» показывают
  человекочитаемое имя текущей клавиши и обновляются при смене.

**Проверено 2026-09-14** (через отдельное UInput-устройство `shepot-test-keyboard`,
т.к. свои `ydotool`-нажатия демон теперь не слушает):
- логика (автономно): смена клавиши пишет в конфиг; назначение занятой
  клавиши отклоняется со статусом «… уже занята …», меню возвращается;
- живьём: `hotkey=KEY_SCROLLLOCK`, `tts_key=KEY_PAUSE` в конфиге → после
  старта Pause читает, Scroll Lock диктует; старые правый Alt/Ctrl не
  срабатывают (0 реакций);
- «на лету» без перезапуска гарантировано тем, что evdev-цикл читает
  `tray.dictate_key`/`tray.read_key` в каждой итерации, а `set_*_key`
  меняет эти поля (клик по GTK-меню — за Мурадом).
