## 1. Назначение

Фоновый демон для Linux (Ubuntu / GNOME) с иконкой в верхней панели. Две
функции, каждая на своей клавише:

| Функция | Клавиша | Как работает | Статус |
|---|---|---|---|
| **Диктовка** (голос → текст) | правый Ctrl, **удерживать** | пока держишь — пишет с микрофона; отпустил — распознаёт (faster-whisper) и вставляет текст в позицию курсора | сделано |
| **Чтение** (текст → голос) | правый Alt, **нажать один раз** | читает вслух выделенный текст, а если выделения нет — от курсора до конца документа; повторное нажатие — стоп | **планируется** (раздел 4) |

Язык — русский. Всё работает локально, без интернета (интернет нужен только
один раз — скачать модель / голос).

## 2. Что уже сделано (диктовка)

### 2.1. Возможности

- **Push-to-talk по правому Ctrl.** Нажатия ловятся через evdev
  (`/dev/input/event*`), поэтому работают в любой программе и под Wayland,
  и под X11. Нужна группа `input`.
- **Модель в памяти постоянно.** `faster-whisper` (`large-v3`, CUDA, `int8`)
  грузится при старте и прогревается; 20 с речи распознаются за ~1.2 с.
- **Длинная диктовка без потерь.** Запись режется на чанки ~30 с в самом
  тихом месте (`find_split`, минимум RMS), чанки распознаются параллельно с
  записью; при отпускании клавиши дораспознаётся только хвост, текст
  склеивается и вставляется одним куском. Каждый чанк сразу пишется в
  `~/shepot-log.txt` — страховка.
- **Вставка текста** (`make_typer()`): X11 → `xdotool type`; Wayland →
  `wl-copy` + `ydotool` Ctrl+V с проверкой, что буфер действительно
  обновился (иначе вставлялось старое содержимое); фолбэк — только буфер
  (`SHEPOT_CLIPBOARD_ONLY=1`).
- **Иконка в панели GNOME** (AppIndicator): статус, последняя фраза, чекбокс
  «Слушать», выход. Окна в доке нет.
- **Менеджер моделей** в подменю «Модель»: каталог faster-whisper +
  HuggingFace, размеры, скачивание с прогрессом, удаление, локальные модели.
  Выбор хранится в `~/.config/shepot/config.json`; при ошибке — откат
  на прежнюю модель.
- **Работа без видеокарты.** Подменю «Устройство»: Авто / GPU / CPU,
  выбор хранится в `config.json`, модель перезагружается на лету. «Авто»
  и «GPU» при отсутствии видеокарты или ошибке загрузки сами уходят на CPU
  (`int8`); в меню видно, где модель реально работает («Авто → CPU»),
  в статусе — «Готов (GPU)» / «Готов (CPU)». Без GPU пункт «GPU» неактивен.
  На CPU `large-v3` медленная — лучше `large-v3-turbo` или `small`.
- **Установщик** `install-shepot.sh`: apt-пакеты, venv, копирование файлов в
  `~/bin`, ярлык в меню и автозапуск.

### 2.3. Архитектура

```
main()
 ├─ Tray (GTK, главный поток)          иконка, меню; UI только через GLib.idle_add
 └─ worker() (фоновый поток)
      ├─ find_keyboards(KEY_RIGHTCTRL)  evdev-устройства с нужной клавишей
      ├─ Recorder                       sd.InputStream открыт всегда, кадры копятся
      │                                 только между start()/pause()
      ├─ jobs: queue.Queue ──► transcriber (один поток владеет моделью)
      │     ("switch", name)            сменить/загрузить модель
      │     ("chunk", session, audio)   распознать кусок
      │     ("finish", session)         склеить и вставить
      ├─ pump(session)                  режет запись на чанки → jobs
      └─ selectors-цикл                 key down → rec.start(); key up → rec.pause()
```

### 2.5. Ограничения железа

GPU — GTX 1080 Ti (Pascal, sm_61): только `int8`, CUDA 12.x + cuDNN 9,
драйвер ветки 580. Подробно — `CONTEXT-shepot.md`, раздел 2.

### 2.6. Известные проблемы

- **GNOME Wayland и вставка текста** — главная. `ydotool` Ctrl+V работает,
  но путь хрупкий; надёжное решение — сессия Xorg (`xdotool`). Детали и
  история — `CONTEXT-shepot.md`, раздел 6.
- Две копии демона делят микрофон — перед отладкой `pkill -f shepot.py`.
- Bluetooth-гарнитура: микрофон только в профиле HSP/HFP (плохой звук).

### 2.7. Windows и macOS (2026-09-25)

- Одна кодовая база, платформенный слой `src/shepot/platforms/`:
  Linux — evdev + GTK/AppIndicator (как раньше); Windows и macOS — pynput
  (глобальные клавиши, Ctrl/Cmd+V), pystray (трей), pyperclip (буфер).
- Чтение вслух на Windows/macOS — выделенный текст через Ctrl+C / Cmd+C
  с возвратом прежнего буфера; «от курсора до конца» — только Linux (AT-SPI).
- GPU: Windows и Linux-сборки несут cuBLAS + cuDNN и переключаются
  Авто / GPU / CPU из меню; macOS — только CPU.
- Сборка: PyInstaller в GitHub Actions → Windows `Setup.exe` (Inno Setup) + zip,
  macOS `.dmg` (arm64 и x64, ad-hoc подпись), Linux AppImage + tar.gz.
  Каждая сборка проходит `--selftest` в CI. Релиз — тег `vX.Y.Z`.
- Подробности и чек-лист проверки — `docs/plans/cross-platform/PLAN.md`.

## 3. Принципы проекта

- Всё локально, GPU нужен только Whisper. Новые функции не должны требовать
  GPU и должны работать на слабых компьютерах.
- Источник правды — файлы в этой папке; после правки — `install -m 755
  shepot.py ~/bin/shepot.py` и перезапуск демона.
- Настройки — только через переменные `SHEPOT_*` и `config.json`; ничего не
  хардкодить.
- Все обновления UI из фоновых потоков — через `GLib.idle_add`.
- Диктовку и чтение не смешивать: отдельный модуль, отдельная клавиша,
  общий только трей и конфиг.

## 4. Новая функция: чтение текста вслух (TTS)

Полный план с этапами и критериями проверки — `docs/plans/tts-reading/PLAN.md`.
Здесь — суть. **Состояние:** этапы 1–3 сделаны 2026-09-14 — движок и
плеер, источники текста (`shepot_reader.py`), стыковка с демоном и меню трея
(`shepot.py`). Впереди этап 4 — установщик и документы.

### 4.1. Как это выглядит для пользователя

1. Ставишь курсор в текст (или выделяешь кусок).
2. Нажимаешь **правый Alt** один раз.
3. Через ~0.3 с начинается чтение. В трее: «Читаю… 3/17».
4. Ещё раз правый Alt — стоп. Нажал правый Ctrl (диктовка) — чтение тоже
   останавливается, чтобы микрофон не записал колонки.

Правила выбора текста:
- есть выделение → читается **только выделенное**;
- нет выделения → **от курсора до конца** документа;
- текста нет (терминал, картинка) → в трее «Нет текста — поставь курсор в
  текст или выдели», ничего не происходит.

### 4.2. Откуда берётся текст

Два способа, пробуются по очереди:

1. **AT-SPI** (шина доступности GNOME, на ней работает экранный диктор Orca).
   У окна в фокусе спрашиваем напрямую: позиция курсора, выделение, текст.
   Клавиши не эмулируются, буфер обмена не трогается. Работает в GTK-
   приложениях, LibreOffice, полях ввода Firefox/Chrome, VS Code.
2. **Клавиши + буфер обмена** — если программа текст через AT-SPI не отдаёт
   (LibreOffice Writer, выделение на веб-странице). Тем же
   `ydotool`/`xdotool`, что и вставка: `Ctrl+Insert` (есть ли выделение?) →
   если нет: `Ctrl+Shift+End` + `Ctrl+Insert` → читаем буфер → `←` и возврат
   курсора через AT-SPI → старый буфер (текст или картинка) восстанавливается.
   Используется `Ctrl+Insert`, а не `Ctrl+C`, чтобы в терминале случайно не
   убить процесс. Терминалы и поля паролей не читаются вовсе.
3. **Только буфер** — режим `SHEPOT_TTS_SOURCE=clipboard`: сам копируешь Ctrl+C,
   демон читает буфер. Для программ, где не работает ничего другое.

### 4.3. Чем озвучивается

- **Piper TTS** — нейросетевой голос, звучит естественно, работает на CPU,
  без GPU. Модель голоса ≈ 60 МБ. Русские голоса из официального каталога:
  `irina` (по умолчанию), `denis`, `dmitri`, `ruslan`. Ставится в тот же
  venv (`pip install piper-tts`), `onnxruntime` уже есть.
- **Запасной движок** — `espeak-ng` (`apt install espeak-ng`, 3 МБ). Звучит
  как робот, зато без нейросети. Отдаёт WAV через `--stdout`, звук идёт через
  тот же плеер, что и у Piper — один путь воспроизведения, один стоп.
  `speech-dispatcher` (`spd-say`) отвергнут: на машине с PipeWire его поток
  зависает в состоянии `init`, звука нет, событие END не приходит.

### 4.4. Чтобы работало на слабых компьютерах

- Текст режется на предложения; синтез идёт на 1–2 предложения вперёд, пока
  играет текущее (та же схема, что чанки в диктовке). Первое слово слышно
  через ~0.3 с, а не после синтеза всего текста.
- Голос грузится при первом нажатии, не при старте демона; потом остаётся в
  памяти (~150 МБ RAM). `SHEPOT_TTS_PRELOAD=1` — грузить сразу при старте.
- Очередь синтеза ограничена (2 предложения) — память не растёт на длинных
  текстах.
- Лимит длины `SHEPOT_TTS_MAX_CHARS` (20 000) — защита от «прочитай мегабайт».
- Арена памяти onnxruntime выключена: с ней одно длинное предложение
  раздувало процесс до 793 МБ навсегда, без неё пик 275 МБ и память
  возвращается (цена — синтез на ~20 % медленнее).
- Piper рассчитан на Raspberry Pi 4; на любом x86 двухъядернике синтез
  быстрее реального времени в разы. **Замер 2026-09-14 (i7, 8 потоков):**
  38.5 с речи за 2.5 с (x15), загрузка голоса 1.0 с, память после чтения
  241 МБ, транзитный пик до ~440 МБ на худшем предложении в 300 символов.
- Whisper не участвует; на слабом ПК его можно не грузить вовсе
  (меню «Устройство» → CPU, модель `tiny`) — это отдельная настройка диктовки.

### 4.5. Трей и настройки

Новое в меню: чекбокс «Читать (…)», пункт «Стоп чтение», подменю
«Голос: irina» (список голосов, размеры, скачивание с прогрессом, как у
моделей Whisper), «Скорость» (0.8× … 2.0×), «Движок» (Piper / espeak),
а также **«Клавиша диктовки»** и **«Клавиша чтения»** — выбор горячей
клавиши из списка безопасных редких клавиш (применяется сразу, без
перезапуска). Выбор сохраняется в `config.json` (`tts_voice`, `tts_rate`,
`tts_engine`, `tts_enabled`, `hotkey`, `tts_key`).

Переменные окружения: `SHEPOT_TTS_KEY`, `SHEPOT_TTS_ENGINE`, `SHEPOT_TTS_VOICE`,
`SHEPOT_TTS_RATE`, `SHEPOT_TTS_SOURCE`, `SHEPOT_TTS_MAX_CHARS`, `SHEPOT_TTS_PRELOAD`,
`SHEPOT_TTS_VOICES_DIR`, `SHEPOT_TTS_BLOCK` — таблица в плане, раздел 9.

### 4.6. Что меняется в файлах

- **новый** `shepot_reader.py` — источники текста, движки, плеер (в `~/bin/`
  рядом с демоном);
- `shepot.py` — только точки стыковки: вторая клавиша в evdev-цикле,
  пункты меню, стоп чтения при нажатии правого Ctrl. Код диктовки не
  меняется;
- `install-shepot.sh` — `pip install piper-tts`, `apt install espeak-ng`,
  копирование модуля, скачивание голоса по умолчанию, включение доступности
  для Firefox/Chrome
  (`gsettings set org.gnome.desktop.interface toolkit-accessibility true`).

### 4.7. Решения, принятые 2026-09-14

| Вопрос | Решение | Почему |
|---|---|---|
| Клавиша | правый Alt | симметрично правому Ctrl; редко используется. Минус: одиночный Alt в Firefox/LibreOffice трогает меню — лечится срабатыванием только на «одиночное» отпускание и опцией раскладки `lv3:ralt_switch` |
| Выделение | читать только выделенное | удобнее читать кусками; без выделения — от курсора до конца |
| Источник текста | AT-SPI, откат на клавиши | чисто там, где можно; работает везде, где работает Ctrl+V |
| Движок | Piper, откат на `espeak-ng --stdout` | естественный голос на CPU; робот — если Piper не установлен. `spd-say` отвергнут: зависает под PipeWire |
